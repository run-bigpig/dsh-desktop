# 会话详情工作区：原生详情验证

验证日期：2026-09-07。实施分支：`feat/session-details-workspace`。

**方案修正已获用户确认。** 测试通过表示下面的现状可复现，不代表统一工作区已实现。

## 范围和结果

使用锁定的 Harness `a66e4702047846cdaa10c66c9d3df3951f5ea70d`、Windows PowerShell 和内置 Node 24.12.0，挂载官方 Layout、Conversation、Chat、Tool、Trajectory 插件。Session 和 Remote 使用 Harness 官方测试运行时提供的 fixture；不请求模型、不启动真实工具、不读取用户会话。

| 检查 | 实际结果 |
| --- | --- |
| 原生工具卡片的 Inspect 按钮 | 切到中间区域的 Trajectory，并展示该会话的工具记录；Chat 的详情选择仍为空 |
| 高优先级工作台占据 `details` | 原生 Inspect 路由保留；右侧显示工作台 |
| 释放工作台并打开 `details` | 恢复原生面板，但仍无选中工具，无法显示刚才检查的工具输出 |
| 关闭、打开原生 details 列 | 不卸载占位组件；实际销毁注册才卸载 |
| 重新声明 `conversation.details.tool` | 注册失败：该子槽仍由原生注册项拥有 |
| 会话切换 | 原生轨迹内容按会话隔离，返回原会话恢复其轨迹内容 |
| 原生宽度 | 公开服务无宽度设置方法；默认 360px，根 store 的宽度动作限制到 520px，关闭重开恢复 360px |

6 项新增现状验证、46 项官方回归测试，共 52 项。新增会话切换测试确认 details 占位会重挂载，不能把资源生命周期绑定到该组件。源码中 `ChatView.tsx` 的 `inspectCall` 调用 `openView('trajectory', callId)`。`apply.ts` 虽然保留 `openDetails(target)` 注入实现，但当前工具点击没有走这条路径；不能由注入接口存在推断产品行为。

替换 `details` 只遮蔽原生展示，不释放其子槽所有权。框架同时禁止重复声明子槽和通过其他注册项的 `renderSlot` 调用该子槽。

## 对实施计划的影响

原计划约定：第一道验证不满足时停止依赖它的实现，不自动扩大 UI 接管范围。本次发现“工具详情 / 返回工作区”通过释放右侧占位即可展示所选工具的前提不成立，因此先调整了实施边界；经用户确认后已开始产品实现，Harness 源码保持不变。

建议修正为：原生工具检查继续留在中间的 Trajectory，右侧工作区只管理文件、Git、浏览器、图片和画布；不新增会打开空面板的“工具详情”入口。用户通过原生 Chat/Trajectory 标签返回对话，右侧工作区可继续保持打开。用户已确认这一修正；后续实施采用该边界。

如果仍要求右侧显示原生选中工具，需要公开的选择/组合接口或另行设计插件自己的工具查看器；不能提取注册表中的组件、借用私有 store 或模拟 DOM 点击实现。

产品实现采用插件持有的会话状态、官方 details 插槽、原生 WebView2 Profile 和独立画布资源生命周期。原生浏览器产品适配器由 `run-browser-runtime.ps1` 验证；原有 `run-browser-workspace.ps1` 仅保留可行性原型证据。

原生层使用 Microsoft.Web.WebView2 1.0.4191.47 的公开 COM 接口；Loader 由 `release/browser.lock.json` 锁定并验证后进入 `resources/browser`。每个会话的 Profile 名使用完整 SHA-256（64 字符，符合官方上限）。截图后台运行通过隐藏子 HWND、保留 WebView2 渲染实现。侧栏发布带序号的布局状态，旧布局不能覆盖较新状态，失联布局会自动隐藏。

画布容器在 details 卸载时移到不可交互的屏幕外区域，保留真实尺寸和编辑器 renderer。插件卸载或会话删除才销毁资源。此容器只承载桌面画布，不替换或复制 Harness 页面。新会话不再提供设计模式；历史设计会话仍通过官方 preset 与存储恢复。

## 复现

在仓库根目录，通过 Windows PowerShell 运行：

```powershell
powershell.exe -NoLogo -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\plugin\probes\run-details-contract.ps1
```

脚本检查 Harness HEAD 与 `release/seed.lock.json` 一致、相关官方 UI 模块无修改；将本目录的测试复制到现有 Desktop 插件测试目录下的唯一临时子目录，通过官方 Vitest 配置执行，最后删除该临时子目录。不复制依赖，不安装包，不执行旧 Desktop 插件源代码。

结果输出：`dist/windows/details-contract-results.json`。执行返回 0 仅代表现状测试通过。产品门禁结论以本报告为准。
