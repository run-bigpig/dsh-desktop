## 决策表

| 问题形态 | 首选能力 | 典型结果 |
|---|---|---|
| 次数、总和、均值、去重用户或趋势 | 事件分析 | 时间序列和分组指标 |
| 按顺序完成且受窗口约束的步骤 | 漏斗分析 | 步骤转化率和流失率 |
| 队列后续回访或流失 | 留存分析 | 队列留存或流失矩阵 |
| 频次、金额、时长或数值分桶 | 分布分析 | 分桶次数或人数 |
| 两个事件之间的耗时 | 间隔分析 | 时间间隔分布和统计量 |
| 某个行为之前或之后的事件序列 | 路径分析 | 前向或后向路径 |
| 按用户属性查看人群组成 | 用户属性分析 | 用户人群分组 |
| 原始记录、自定义关联或模型不支持的公式 | 只读 SQL | 经过验证的表格结果 |
| 查询某个模型结果单元格对应的用户 | 模型用户列表 | 用户级证据 |

## 请求构造

已确认的项目、事件和属性可以直接复用，不要为每次查询重复发现元数据。

1. 未确认项目时先解析 `project_id`。
2. 未确认事件或属性时再按项目检索内部名和 `table_type`。
3. 按工具输入结构的 snake_case 字段构造最小请求，不传 TA camelCase 原始对象。
4. 需要可复现结果时使用绝对时间范围。
5. 在解释中明确项目时区。
6. 选择用户身份或分析主体。
7. 确认属性类型后再添加筛选条件。
8. 限制分组基数和响应规模。

## 事件分析

用于指标趋势、分组对比和贡献分析。

- 使用 `TOTAL_TIMES` 统计事件次数。
- 使用 `TRIG_USER_NUM` 统计触发用户数。
- 只有确认属性为数值类型后才使用数值聚合。
- 解释比率变化前，先拆开分子和分母。
- 按绝对变化量排序维度，不能只看变化百分比。

## 漏斗分析

仅在步骤顺序和完成窗口有业务含义时使用。

- 每一步必须对应真实事件。
- 定义起始人群和用户身份。
- 完成窗口要符合真实业务路径。
- 已知用户与结果不符时查询用户明细。
- 判断数据丢失前先验证顺序和窗口规则。

## 留存分析

用于初始事件队列后续回访或流失。

- 分开定义初始事件和回访事件。
- 注册队列不能与全量活跃用户混用。
- 不得直接比较留存队列值和无队列限制的事件均值。
- 结果有争议时，使用相同初始人群复算。

## 分布分析与间隔分析

分析数值或频次形态时使用分布分析；分析两个行为之间耗时时使用间隔分析。

- 偏态分布不能只报告均值，应查看尾部分桶；需要精确分位数时再使用支持的聚合或 SQL。
- 有业务意义时保留零值或未回访人群。
- 稀疏分桶必须报告样本量。

## 路径分析

用于探索某个核心行为前后的行为序列。

- 明确前向或后向方向。
- 限制路径长度和时间窗口。
- 路径只能作为描述性证据，不能直接证明因果。
- 重要路径分支应使用漏斗或事件分析验证。

## 用户属性分析

用于查看稳定属性或当前用户属性的人群组成。

- 确认属性代表当前状态还是事件发生时状态。
- 禁止用事件属性替代用户属性。
- 可变用户属性可能改变历史解释，需要明确说明。

## 用户级下钻

模型用户列表不是独立的首次查询入口。先运行对应模型，再：

1. 原样复用模型中的 `project_id`、`event_view` 和 `events`。
2. 从模型结果复制目标单元格对应的日期、分组、区间、步骤或路径层级。
3. 按用户列表输入结构填写切片参数；不要根据展示文本猜坐标。
4. 用户列表仍过大且该模型存在用户下载工具时，再执行用户下载。
5. 需要单个用户行为序列时，从用户列表取得真实 `user_id` 后调用用户事件列表。

不要把用户列表中的局部人数直接当作全局指标，也不要在改变原模型条件后继续声称
下钻的是原结果单元格。

## 常见组合

### 异常诊断

1. 事件分析确认异常。
2. 拆分分子和分母。
3. 按最可能的维度分组。
4. 使用漏斗、留存或分布定位行为断点。
5. 使用用户列表或 SQL 验证样本。

### 渠道或投放计划质量

1. 事件分析统计获客规模和收入。
2. 漏斗分析统计激活或付费转化。
3. 留存分析统计后续用户质量。
4. 只有提供成本数据后才能计算成本指标。
5. 按 ROI 或绝对贡献排序，不能只看 CTR 或 CPI。

### 关卡流失

1. 查找流失用户最后尝试或完成的关卡。
2. 按关卡比较通关率和尝试次数。
3. 与历史基线或老用户比较。
4. 使用人群分层验证疑似关卡。

### LTV 分析

1. 定义队列和收入范围。
2. 统一累计收入或分日收入的计算方式。
3. 查询各观察日真实累计 LTV。
4. 使用付费层级和成熟队列验证结果是否被少量用户主导。

## 选择误区

- 需要顺序转化时不得用事件分析替代漏斗分析。
- 行为无顺序关系时不得强行使用漏斗。
- 复现队列时不得把结果分群当作条件分群。
- 模型能够直接回答时，不要先写 SQL。
- 已有准确内部名时，不要为了形式完整重复查询全部元数据。
- 不要把下载工具作为普通查询入口；下载不会直接返回可分析的数据正文。
