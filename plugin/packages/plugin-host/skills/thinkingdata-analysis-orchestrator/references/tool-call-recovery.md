# ThinkingData 工具调用与恢复

## 目标

减少因为工具描述不完整、服务端运行时约束、响应过大或二段式取数造成的无效重试。
只修正失败字段或查询范围，不改变业务定义。

## 项目和元数据发现

项目名来自口语、拼写错误或缩写时：

1. 先用 `ta_search_metadata` 搜完整词；
2. 无结果时拆成稳定关键词分别搜索；
3. 仍不明确时调用 `ta_list_projects(active_only: true)`；
4. 人工匹配显示名后记录 `project_id`；
5. 项目确定后，事件和属性只使用带 `project_id` 的 `ta_list_events`、
   `ta_list_properties`，避免跨项目噪声。

`ta_search_metadata` 返回 `projects: null` 不是权限错误，也不证明项目不存在。不要根据
相似项目名猜 `project_id`。

查找渠道、版本、国家等维度时，同时考虑事件属性和用户属性：

- 事件属性描述行为发生时状态；
- 用户属性通常描述首次归因或当前稳定状态；
- 同一关键词在一个 `table_type` 无结果时，不得认定字段不存在，应按业务语义检查另一个
  `table_type`；
- 不得用事件属性冒充稳定归因字段，也不得用当前用户属性解释历史事件快照。

## 最小模型调用

第一次调用分析模型时：

- 使用绝对时间；
- 只提交必要事件和参数；
- 不加无用途的分组和过滤；
- 先用小日期范围验证参数枚举和返回结构；
- 首次验证或争议复算可设置 `use_cache: false`；
- 完全相同且已验证的重读才考虑 `use_cache: true`。

留存模型的运行时约束：

- `stat_type`: `retention` 或 `lost`；
- 事件 `type`: `first`、`second`、`simultaneous_display`；
- 日 LT 使用 `time_particle_size: day`；
- `unit_number: n` 表示返回到 Dn。

遇到通用 `-1004` 时，不要立即更换事件或口径。先把注册范围缩到单日验证；单日成功后，
将原注册范围拆成不重叠的小块并合并人数。通用错误只能证明该请求整体失败，不能直接
解释为无数据、字段错误或业务异常。

## 大响应处理

留存、路径、长时间事件结果和用户明细可能很大。能够使用对应下载工具时，优先让数据
通过临时 HTTP 文件流转，不把完整响应注入模型上下文。

### 下载选择

- 模型汇总数据量大：直接使用对应分析下载工具。
- 用户明细量大：先从最小模型结果取得准确切片坐标，再使用对应用户下载工具。
- 已经明确需要全量文件时，不要先运行相同范围的普通结果工具验证数据量。
- 路径分析没有结果下载，漏斗和路径没有用户下载；这些场景缩小范围或改用只读 SQL。

下载结果包含 `filename`、`download_url`、`bytes`、`content_type` 和 `expires_at`。
收到结果后立即获取文件。`download_url` 包含临时访问令牌，不附加 MCP Bearer Token，
也不在日志、脚本源码、最终报告或长期文件中保存完整地址。

### Python 文件分析

为当前业务问题编写最小 Python 脚本，脚本只输出紧凑的 JSON 或表格摘要。处理规则：

1. 下载地址只作为运行时输入，禁止在脚本中硬编码或打印。
2. 先核对 HTTP 状态、实际文件大小和 `content_type`，再解析数据。
3. CSV 使用 `pandas.read_csv(..., chunksize=...)` 或逐行读取，禁止一次性加载未知大小文件。
4. NDJSON 逐行解析；XLSX 使用 `openpyxl` 的只读模式。
5. 每个分块只累计目标指标、分组统计、去重集合或校验信息。
6. 最终只输出列名、行数、类型、空值、目标聚合、异常计数和少量脱敏样本。
7. 聚合前后核对处理行数；分块合并时验证日期范围、分组键和去重口径没有变化。

若文件超过单机可安全处理的内存，继续缩小列和日期范围，或使用分块外部聚合；不得为了
方便把完整文件内容返回对话上下文。地址过期返回 404 或 410 时，重新调用下载工具取得
新地址，不重复请求旧地址。

### 无下载工具时

没有对应下载工具的模型，调用后立即在编排层抽取：

- 查询是否成功；
- 结果生成时间；
- 初始人数或总人数；
- 必要的日期、分组和数值数组；
- 后续下钻所需的精确切片坐标。

不要把完整响应转成文本后再让模型人工读取。这样容易触发输出截断，并丢失末尾字段。
优先读取 `structuredContent.result`；仅在结构化结果不存在时解析 `content` 中的文本。

独立分块可以并行执行。每块只返回紧凑摘要，最后统一做一致性校验。

高基数国家、版本、商品或长日期结果必须在调用编排层按目标组抽取。输出被截断后，不得根据
可见片段判断分组总数、总和或转化率；应重新调用并只返回所需分组和指标。

## 筛选值与字典属性

- `comparator` 是 TA 运行时参数，不要根据通用 SQL 或其他分析系统猜枚举。等值筛选优先使用
  已验证可用的 `equal`；若成功响应却为空，先用已知存在的属性值做最小筛选验证，再只修正
  比较符。
- 元数据中的 `dictProps` 是父属性的字典展示配置，不保证能够作为独立 `property_name` 查询。
  `ta_get_property` 找不到 `product_id@des` 等字典子属性时，保留原始 ID 分析，不要设置
  `allow_unknown_metadata` 强行查询。
- 元数据不返回取值枚举。渠道名、版本号、商品 ID 等筛选值必须来自用户输入或已有查询结果。

## SQL 工具差异

### `ta_query_sql`

适合小结果。常见返回是 `result.data` 中的 NDJSON 文本：第一行可能是状态对象，后续行
才是数据。解析时跳过没有业务列的状态行。

`SHOW TABLES`、`SHOW` 或 `DESCRIBE` 可能因权限返回 `-1006`。发生后停止该路径，改用
项目元数据或带 `$part_date` 的最小 `SELECT`。事件表即使有 `LIMIT 1`，仍必须添加日期
分区条件。

若项目与事件表存在经过验证的命名映射，可以把映射生成的表名当作“候选”，用最小查询
确认，而不能直接当作事实。例如候选为 `v_event_<project_id>` 时：

1. 先执行带 `LIMIT 1` 的只读查询；
2. 如果服务端返回“该事件表查询必须包含 `$part_date`”，可据此判断候选表已被解析为
   真实事件表，而不是表不存在；
3. 加上最窄的 `$part_date` 条件重新执行，读取一行确认真实字段；
4. 如果返回表不存在，则停止猜测并回到元数据或既有表映射；
5. 表存在只证明物理访问成功，不证明项目时区、用户身份和分析模型口径一致。

禁止连续尝试多个相似表名碰运气。只有已有项目 ID 和可靠命名约定时才能使用该恢复方式，
并在结论中标记表名是如何确认的。

### `ta_execute_sql`

- `page_size` 实际最小值为 1000；
- 成功响应可能只有 `taskId`、`headers`、`pageCount` 和 `rowCount`；
- 这不是空结果；使用 `taskId` 调用 `ta_sql_result_page(page_id: 0)`；
- 根据 `pageCount` 继续获取后续页；
- 不得因为未直接看到数据行而重新执行 SQL。

### `ta_submit_sql`

用于已知的大查询。保存 `task_id`，轮询 `ta_sql_task_info`；完成后从 `page_id: 0` 获取
结果。只轮询当前工作流创建的任务。

## 长任务和外层执行器

如果外层执行器返回 session、cell 或“仍在运行”标识：

1. 保存标识；
2. 使用对应 wait 或 poll 工具获取增量输出；
3. 不要重新提交 TA 工具调用；
4. 等待完成后再解析最终结果。

重新提交会制造重复负载，并可能得到时间点不同的两份结果。

## 本次已验证错误映射

| 信号 | 原因或含义 | 最短修复 |
|---|---|---|
| `projects: null` | 搜索词未命中，不等于项目不存在 | 拆关键词，再 `ta_list_projects` |
| 等值筛选成功但无分组 | 比较符或属性表语义可能不匹配 | 用已知值和最小请求验证 `equal`、`table_type` |
| 字典子属性查询不到 | `dictProps` 不一定是独立属性 | 使用父属性原始 ID，停止强查字典字段 |
| `eventView.statType` 正则错误 | 传入了非 `retention|lost` 值 | 只修正 `stat_type` |
| 留存 `-1004` | 整体请求失败，原因不够具体 | 单日验证，再拆注册范围 |
| `executeSql.pageSize` 最小值错误 | 运行时下限为 1000 | 设置 `page_size: 1000` |
| SQL 成功但只有 `taskId` | 二段式分页结果 | 调用 `ta_sql_result_page` |
| `SHOW TABLES` 权限错误 | 当前账号不允许表发现 | 改用元数据或最小分区查询 |
| 事件表要求 `$part_date` | 查询被性能保护拒绝 | 添加最窄日期分区 |
| 模型与 SQL 人数不一致 | 时间、身份或合并规则未复现 | 停止用 SQL 覆盖模型，先对齐口径 |

## 禁止事项

- 禁止用完全相同参数重复失败调用；
- 禁止为了让工具成功而静默缩短业务观察窗；
- 禁止把 `taskId` 元数据响应解释成零行；
- 禁止在大响应被截断后凭可见片段计算结果；
- 禁止在模型与 SQL 未对齐时挑选更符合预期的数字；
- 禁止丢失分块日期范围、任务 ID 或分页位置。
